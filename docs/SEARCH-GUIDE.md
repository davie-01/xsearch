# XSearch 搜索语法与正则指南

核对日期：2026-11-04。面向桌面应用的搜索框，按当前源码与测试核对，只描述已实现的语法；早期 `xs` CLI 的语法见其 `help` 输出。部分示例未逐项在界面中验收，若行为与本文不符，以所运行版本为准并请反馈。

## 1. 先分清两种搜索模式

| 模式 | 搜索什么 | 如何进入 |
| --- | --- | --- |
| 名称搜索 | 应用名称、文件名、文件夹名 | 启动器按 `⌘1`；完整窗口选择名称模式或按 `⌘1` |
| 内容搜索 | 已提取并建立内容索引的文档正文 | 启动器输入 `in `，或按 `⌘2`；完整窗口选择内容模式或按 `⌘2` |

启动器默认呼出快捷键为 `⌥Space`，可以在设置中修改。默认呼出名称模式，也可以设置为记住上次模式。

```text
试运行
```

在名称模式查名称中包含“试运行”的项目。

```text
in 试运行
```

在快捷启动器进入内容模式，查正文中包含“试运行”的文档。输入后 `in ` 会转成界面里的“内容”标记，不再留在输入文字中。

注意：

- 前缀必须是开头的小写 `in` 加一个英文空格。`in:`、`IN `、`find ` 不是同一个指令。
- `in ` 的自动模式切换在快捷启动器实现。完整窗口请直接切换模式，再输入查询，不要依赖它自动识别此前缀。
- 已进入内容模式后，不必每次再输入 `in `。下文内容搜索示例中的 `in ` 用于方便从启动器直接开始。
- 内容模式的普通关键词搜索正文，不会同时要求文件名包含关键词。

## 2. 指令总表

| 写法 | 功能 | 名称模式 | 内容模式 | 例子 |
| --- | --- | --- | --- | --- |
| 普通文字 | 包含关键词 | 支持 | 支持 | `示例智慧城市` |
| 英文空格 | 多个关键词同时出现，AND | 支持 | 支持 | `示例 报告` |
| `"…"` | 把其中的空格、运算符作为字面文字 | 支持 | 支持 | `"年度 报告"` |
| `\` | 转义后面的特殊字符 | 支持 | 支持 | `\-草稿` |
| `\|` | 任一条件出现，OR | 支持 | 支持 | `合同 \| 协议` |
| 前置 `-` | 排除紧随的文字表达式 | 支持 | 支持 | `合同 -草稿` |
| `(…)` | 对文字表达式分组 | 支持 | 支持 | `(合同 \| 协议) -草稿` |
| `dir:` | 限制搜索目录及其后代范围 | 支持完整路径和目录名片段 | 只支持完整路径 | `dir:~/Documents` |
| `ext:` | 按扩展名过滤 | 支持 | 支持 | `ext:pdf;docx` |
| `kind:` | 按文件类别过滤 | 支持 | **不支持类别过滤** | `kind:folder` |
| `size:` | 按磁盘文件大小过滤 | 支持，排除文件夹 | 支持 | `size:>10mb` |
| `dm:` | 按最后修改时间过滤 | 支持 | 支持 | `dm:7d` |
| `*`、`?`、`**` | 通配符匹配 | 支持 | 不作为通配符解释 | `*试运行*.pdf` |
| `regex:` | 正则表达式匹配 | 名称或路径 | 已提取正文 | `regex:HT-[0-9]{4}` |
| `"甲 乙"~N` | 多个词在一定字符间距内出现 | 不支持邻近语义 | 支持 | `in "合同 金额"~10` |

运算符、通配符、正则、邻近查询可在 **设置 → 搜索语法** 分别开关；默认配置均开启。关闭后的对应符号按普通文字处理，不能直接照搬开启时的例子。在启动器按 `⌘/` 可查看速查及开关状态。

指令使用英文冒号、英文双引号、英文括号等符号。建议前缀后不加空格，例如写 `ext:pdf`，不要写 `ext: pdf`。

## 3. 普通关键词、短语与布尔组合

### 3.1 普通文字：默认就是“包含”

```text
示例智慧城市
```

名称模式可以匹配 `009-示例智慧城市项目`，不必加星号。这里是包含匹配，不是仅匹配开头。普通词只查名称，不因为写了 `/` 就自动变成路径查询。

名称匹配不区分大小写；它不提供拼音或拼音首字母转写，也不承诺错字纠正。名称匹配与内容模式的归一化规则不同，不要认为内容匹配设置会改变文件名搜索。

### 3.2 空格：多个词同时包含，顺序不限

```text
示例 试运行
```

要求同一个名称中同时包含“示例”和“试运行”。

```text
in 合同 金额
```

要求同一份提取正文中同时有两个词，可以分布在不同位置；不要求相邻。

### 3.3 双引号：把空格和符号作为文字

```text
"年度 报告"
"合同(正式版)"
"dir:合同"
```

分别搜索包含空格的连续文字、包含括号的名称、字面上的 `dir:合同`。引号不代表整份名称或整份文档必须完全相等；需要整名匹配时使用带首尾锚点的正则。

内容模式下，短语是否严格保留空白差别还取决于“宽松／区分大小写／严格原文”设置。

### 3.4 OR、NOT、分组

| 输入 | 含义 |
| --- | --- |
| `合同 \| 协议` | 名称包含任一词 |
| `合同 -草稿` | 名称含合同，且不含草稿 |
| `合同 -(草稿 \| 作废)` | 名称含合同，同时排除含草稿或作废的项目 |
| `(合同 \| 协议) 2026` | 名称含合同或协议，并且含 2026 |
| `in (验收 \| 试运行) -作废` | 正文含验收或试运行，且正文不含作废 |

优先级为：前置排除优先于空格 AND，AND 优先于 OR；复杂条件建议明确加括号。`AND`、`OR`、`NOT` 三个英文单词本身不是运算符。

纯排除查询如 `in -草稿` 可以产生很大的候选集合，通常加上正向关键词及 `dir:`、`ext:` 更实用。内容模式语法未写完整时可能显示解析错误，例如缺少右括号或引号；补完整后再判断结果。

### 3.5 转义

```text
\-草稿
合同\(正式版\)
"甲|乙"
```

分别搜索字面上的 `-草稿`、`合同(正式版)`、`甲|乙`。一般优先用双引号包住有特殊符号的普通名称；名称通配符中的星号要作为文字时，也可以将整段加引号。

## 4. `dir:`：限定在哪个目录里搜索

### 4.1 完整路径与用户目录

```text
报告 dir:~/Documents
报告 dir:/Users/me/Documents
in 试运行 dir:~/Documents
```

`~` 表示当前用户主目录。范围通常包含指定目录的后代项目，不是只查第一层。名称模式用于限制目录里的结果，并不是用来查找该目录本身；要找文件夹本身，使用关键词加 `kind:folder`。

路径必须按实际文件系统路径填写，不要仅凭 Finder 的本地化显示名称替换实际目录名。

### 4.2 路径中有空格

```text
试运行 dir:"/Users/me/Documents/Work Files/客户项目/009-示例智慧城市项目"
in 试运行 dir:"/Users/me/Documents/Work Files/客户项目/009-示例智慧城市项目"
```

给冒号后面的路径加英文双引号，前缀 `dir:` 留在引号外。完整路径两种模式都适用。

### 4.3 名称模式专用：目录名片段

```text
报告 dir:合同
报告 dir:合同/2024
```

第一条在名称为“合同”的目录及其后代中找；第二条要求连续的目录层级名为“合同／2024”。

这里“片段”是路径层级片段，**每一层目录名要匹配完整名称**，不是任意子串。例如 `dir:示例智慧城市` 不会自动指向 `009-示例智慧城市项目`；应写完整目录名片段或完整路径。

内容模式不支持这种片段写法。`in 报告 dir:合同` 会提示需要完整路径；无效目录条件不会发挥预期的范围限制。

### 4.4 多个目录：取并集

```text
合同 dir:~/Documents dir:~/Downloads
```

在两个目录中的任意一个搜索，不是要求一个项目同时属于两个目录。每个路径分别写一个 `dir:`，不要用分号拼成一个路径。

`dir:` 是查询范围，不是新建索引指令。它不会自动给整个目录建立内容索引，也不会自动读取所有原文件。未建内容索引的目录若出现“实时扫描其中的文本文件”，需显式点击；该功能只扫描支持的文本类文件，不等于实时提取全部 PDF、Word 或图片。

## 5. `kind:`：按类别找文件、文件夹或应用

**仅名称模式识别 `kind:` 类别过滤。** 类别是按目录／应用标记及扩展名分组，不是全文内容的语义分类。

| 类别 | 可接受的值（别名） | 当前分组范围 |
| --- | --- | --- |
| 文件夹 | `folder`、`dir`、`directory`、`文件夹`、`目录` | 目录项目 |
| 应用 | `app`、`application`、`应用` | 应用项目 |
| PDF | `pdf` | pdf |
| 文字文档 | `doc`、`word`、`文档` | doc、docx、wps、rtf、pages、odt |
| 表格 | `xls`、`excel`、`sheet`、`表格` | xls、xlsx、csv、numbers、ods、et |
| 演示文稿 | `ppt`、`slide`、`powerpoint`、`演示` | ppt、pptx、key、odp、dps |
| OFD | `ofd` | ofd |
| 文本和代码 | `text`、`txt`、`code`、`文本`、`代码` | 见下方完整列表 |
| 图片 | `image`、`img`、`picture`、`图片` | png、jpg、jpeg、gif、heic、heif、webp、tif、tiff、bmp、svg、raw、dng |
| 视频 | `video`、`视频` | mp4、mov、m4v、avi、mkv、webm |
| 音频 | `audio`、`music`、`音频` | mp3、m4a、aac、wav、flac、aiff、ogg |
| 压缩包和镜像 | `archive`、`zip`、`压缩包` | zip、rar、7z、tar、gz、tgz、bz2、xz、dmg、iso |

`kind:text` 的扩展名分组为：

```text
txt md markdown log json xml yaml yml toml ini
swift rs c h m mm cpp hpp py js ts tsx jsx go java kt rb sh zsh html css sql
```

用法：

```text
示例智慧城市 kind:folder
合同 kind:doc
试运行 kind:pdf
预算 kind:sheet
Safari kind:app
合同 kind:pdf;word
```

`kind:pdf;word` 接受任一类别；也可用英文逗号分隔或重复写 `kind:`。

容易误解的地方：

- `kind:doc` 不是只查 `.doc`；只查该后缀要写 `ext:doc`。
- `kind:zip` 是整个压缩包／镜像类别，不是只查 `.zip`。
- `kind:docx`、`kind:xlsx`、`kind:其他`、`kind:other` 当前不是有效别名；精确后缀请用 `ext:`。
- 名称类别与内容提取支持范围不同：名称模式能找到某后缀，不代表该格式已完成内容提取或索引。
- 内容模式中的 `kind:pdf` 不会变成类型过滤，通常会作为正文文字参与查询。请改用 `in 关键词 ext:pdf`。

应用启动结果有单独的名称索引。普通应用名和 `Safari kind:app` 是常用路径；通配符、正则、复杂布尔条件及只有 `kind:app` 的查询，不保证枚举与普通应用名搜索相同的完整应用集合。更复杂的应用条件可能依赖文件名索引是否收录对应 `.app`。

## 6. `ext:`：只看指定扩展名

```text
合同 ext:pdf
合同 ext:doc;docx
合同 ext:doc,docx,pdf
in 试运行 ext:pdf;docx
```

两种模式都支持，不区分后缀大小写；前导点可省略，也接受 `ext:.pdf`。多个后缀取并集；重复写 `ext:` 也会合并。

`ext:docx` 与 `kind:doc` 不同：前者是一个精确后缀，后者是一组类别。

`ext:` 中不要写通配符，例如 `ext:*.pdf` 不等于 `ext:pdf`。该条件只筛选已有候选，不会让未支持的文件格式自动具有全文搜索能力。

## 7. `size:`：按文件大小过滤

大小是磁盘文件的字节数，不是字数、页数或提取后正文大小。名称模式加 `size:` 会排除目录，不能用它计算文件夹内所有文件的合计大小。

| 输入 | 含义 |
| --- | --- |
| `size:>10mb` | 大于 10×1024×1024 字节 |
| `size:>=10mb` | 大于或等于上述大小 |
| `size:<1m` | 小于 1×1024×1024 字节 |
| `size:<=500k` | 小于或等于 500×1024 字节 |
| `size:empty` 或 `size:空` | 大小为 0 字节的文件 |
| `size:1024` | 恰好 1024 字节 |
| `size:>=1m size:<=10m` | 精确限制在 1 MiB 至 10 MiB，包含两端 |

支持单位 `b`、`k/kb`、`m/mb`、`g/gb`、`t/tb`，不区分大小写，均为 1024 进制；省略单位即字节。可以使用小数，例如 `size:>1.5m`。

**当前实现的特殊规则：单独写带单位的值或区间，上界按单位桶扩展。**

- `size:1m`（包括 `size:=1m`）表示 1 MiB 至小于 2 MiB，不是恰好 1 MiB。
- `size:1m..2m` 表示 1 MiB 至小于 3 MiB，不是通常直觉中的 1–2 MiB。
- 若希望精确的上下限，推荐用两个比较条件，例如 `size:>=1m size:<=2m`。

组合例子：

```text
试运行 ext:pdf size:>10mb
in 合同 ext:docx size:<=20m
```

## 8. `dm:`：按最后修改时间过滤

`dm` 指修改时间，不是创建时间，也不是索引时间。时间按本机日历和时区解释；本周起始日随本机日历配置。

### 8.1 快捷时间

| 英文 | 中文别名 | 含义 |
| --- | --- | --- |
| `today` | `今天` | 今天的自然日 |
| `yesterday` | `昨天` | 昨天的自然日 |
| `thisweek` | `本周` | 当前自然周 |
| `lastweek` | `上周` | 上一个自然周 |
| `thismonth` | `本月` | 当前自然月 |
| `lastmonth` | `上月` | 上一个自然月 |
| `thisyear` | `今年` | 当前自然年 |
| `lastyear` | `去年` | 上一个自然年 |

```text
报告 dm:today
合同 dm:本月
in 试运行 dm:7d
```

相对时间支持正整数加 `d/天`、`w/周`、`m/月`、`y/年`。例如 `7d` 是从查询时刻向前推 7 天直到现在，`3m` 是向前推 3 个日历月；不等于三个自然月的完整范围。

### 8.2 日期、比较与区间

| 输入 | 含义 |
| --- | --- |
| `dm:2026` | 2026 全年 |
| `dm:2026-11` | 2026 年 11 月 |
| `dm:2026-11-04` | 指定自然日 |
| `dm:>=2026-11-01` | 从该日开始及以后 |
| `dm:>2026-11-01` | 在该日结束之后，即从次日开始 |
| `dm:<=2026-11` | 截至 2026 年 11 月结束 |
| `dm:<2026` | 2026 年开始之前 |
| `dm:2026-01..2026-06` | 2026 年 1 月开始至 6 月结束 |

日期也接受 `/` 或 `.` 作为年月日分隔符，但建议统一使用 `YYYY-MM-DD`。日期区间包含两端对应的完整周期。重复写 `dm:` 取交集，例如 `dm:>=2026-01-01 dm:<2027-01-01`。

## 9. 名称模式通配符：`*`、`?`、`**`

前提：设置中开启通配符。内容模式不会把这些符号解释成名称通配符；若需按后缀限制正文结果，用 `ext:`。

| 符号 | 含义 |
| --- | --- |
| `*` | 匹配零个或多个字符，不跨 `/` |
| `?` | 匹配一个 Unicode 标量，不匹配 `/`；一般汉字按一个，复杂组合 emoji 不一定按一个 |
| `**` | 匹配零个或多个字符，可以跨 `/` |

通配符是**整段匹配**：不含 `/` 时匹配整个名称；含 `/` 时匹配完整路径。普通文字的包含匹配与它不同。

| 示例 | 含义 |
| --- | --- |
| `*.pdf` | 名称以 `.pdf` 结尾 |
| `试运行*` | 名称以试运行开头 |
| `*试运行*` | 名称任意位置包含试运行 |
| `*试运行.pdf` | 名称以试运行.pdf 结尾 |
| `报告?.docx` | 报告后面恰有一个字符，再接 .docx |
| `**/合同/*.pdf` | 任意位置名称为合同的目录直接包含的 PDF；最后的 `*` 不跨子目录 |
| `/Users/me/Documents/**` | 指定路径下匹配后续各级路径 |

相对路径通配符如 `合同/*.pdf`，实现会补上前面的任意祖先路径。不要把本应用的 `**` 当成所有 shell 或 Git glob 的完整语法；这里没有单独实现“`**/` 自动连同斜杠一起省略”的规则。

以 `009-示例智慧城市项目` 为例：

- `示例智慧城市`：普通包含匹配，可以命中。
- `*示例智慧城市`：要求名称以“示例智慧城市”结束，不能匹配末尾还有“项目”的名称。
- `*示例智慧城市*`：允许两侧都有其他文字，可以命中。
- `示例智慧城市 kind:folder`：只看名称包含该词的文件夹，通常最直接。

通配符中 `[0-9]` 不作为字符组使用；需要数字规则请使用 `regex:`。

## 10. `regex:`：正则表达式

### 10.1 基本写法与作用对象

```text
regex:表达式
```

不需要额外包一对 `/…/`，也不要给整个正则加外层双引号。普通空白会结束正则 token，所以应使用 `\s`、`\s+` 或 `\x20` 表达模式里的空白。

| 模式 | 实际匹配对象 |
| --- | --- |
| 名称模式，表达式不含 `/` | 文件或文件夹名称；包括扩展名 |
| 名称模式，表达式含 `/` | 完整路径 |
| 内容模式 | 提取后的正文；受当前内容匹配模式影响 |

正则默认是“存在一个匹配即可”。名称要整名匹配时加 `^` 和 `$`；内容模式的首尾锚点默认针对整份提取正文，不是每一行。查逐行模式可以使用 `(?m)`；宽松模式可能将换行合并为空格，若需要原始行结构，应选择严格原文，并注意 PDF 等格式的“原文”仍是提取文本。

正则 token 会一直读取到普通空白，内部的 `|` 和括号属于正则本身。与外层查询组合时，用空格分隔：

```text
regex:HT-[0-9]{4} -草稿
(regex:HT-[0-9]{4} | 合同)
```

第二条外层右括号前有空格，使它不被正则 token 吞入。

### 10.2 常用符号速查

| 正则符号 | 含义 | 示例 |
| --- | --- | --- |
| `.` | 通常为任意一个非换行字符 | `报告.` |
| `.*` | 任意长度的上述字符 | `合同.*正式` |
| `.+` | 至少一个上述字符 | `报告.+` |
| `?` | 前一项出现零次或一次 | `报告-?2026` |
| `[0-9]` | 一个 ASCII 数字 | `[0-9]{4}` |
| `[A-Za-z]` | 一个 ASCII 英文字母 | `[A-Za-z]+` |
| `\d` | 一个 Unicode 数字，范围比 0–9 广 | `\d+` |
| `\s` | 一个空白字符 | `合同\s+金额` |
| `\S` | 一个非空白字符 | `编号\S+` |
| `{n}` | 前一项恰好出现 n 次 | `[0-9]{4}` |
| `{n,m}` | 前一项出现 n 至 m 次 | `[0-9]{2,4}` |
| `^`、`$` | 起始／结束位置 | `^报告.*\.pdf$` |
| `\.` | 字面上的英文点 | `\.docx$` |
| `(甲\|乙)` | 正则内部二选一 | `(合同\|协议)` |
| `(?:…)` | 非捕获分组 | `\.(?:pdf\|docx)$` |

### 10.3 可复制的名称正则

```text
regex:^009-.*
regex:^009-示例智慧城市项目$ kind:folder
regex:^报告[0-9]{4}\.pdf$
regex:(合同|协议).*\.(pdf|docx)$
regex:试运行.*\.pdf$
regex:/合同/[^/]*\.pdf$
```

依次表示：名称以 009- 开头；精确匹配指定文件夹名；报告＋四位数字的 PDF；名称含合同或协议、并以指定后缀结束；名称含试运行的 PDF；路径中合同目录直接包含的 PDF。

### 10.4 可复制的内容正则

```text
in regex:HT-[0-9]{4}-[0-9]+ ext:pdf;docx
in regex:合同编号[:：]?\s*[A-Za-z0-9-]+ ext:pdf;docx
in regex:[0-9]{4}-[0-9]{2}-[0-9]{2} dir:~/Documents
in regex:1[3-9][0-9]{9} ext:txt
in regex:金额[:：]?\s*[0-9,]+(?:\.[0-9]{1,2})? ext:pdf
```

这些是文本形状匹配，日期例子不校验真实日历有效性，手机号例子不保证号码实际分配有效。

内容正则若没有足以召回候选的固定文字，又没有 `dir:` 或 `ext:`，应用可能拒绝全库扫描并提示：

```text
正则需要包含至少 3 个字节的固定文字，或搭配 dir: / ext: 缩小范围
```

最稳妥的写法是添加目录或扩展名。这里是 **3 个 UTF-8 字节，不是 3 个汉字**；最终是否能提前召回，还取决于整个表达式是否能形成安全的候选条件。单独加 `size:` 或 `dm:` 不能替代此处要求的目录／扩展名范围。

### 10.5 两种模式的引擎差异

- 名称正则使用 `NSRegularExpression`，匹配已做名称大小写折叠的键；不能靠切换内容匹配设置恢复名称的原始大小写。
- 内容正则使用 Rust `regex`。它不支持前后查找（look-around）和反向引用，例如 `(?<=合同)` 或 `(词)\1` 不能作为可移植的内容查询写法。详见 [Rust regex 官方语法说明](https://docs.rs/regex/1.13.1/regex/#syntax)。
- 内容正则匹配的是当前模式处理后的正文；正则表达式本身不会像普通关键词一样自动做同一套全文归一化。涉及全角字符或严格行结构时，优先使用严格原文并按实际提取文本编写。
- 正则不承诺文件替换或批量重命名；这里只用于查找和定位。

## 11. 内容邻近查询：`"甲 乙"~N`

```text
in "合同 金额"~10
in "试运行 报告"~20 ext:pdf
```

含义是这些词都出现在一个局部窗口内，词的顺序不限，窗口内除各关键词以外的字符数不超过 N。按当前匹配模式处理后的字符计算，不是按单词数、页数或字节数计算，也不限定在同一段落。

例如正文“合同的总金额”中，合同和金额之间有“的总”两个字符：`"合同 金额"~2` 可以匹配，`~1` 不匹配。对于三个及以上关键词，N 约束的是覆盖这些词的窗口，不是每两个相邻词分别都允许 N。

至少提供两个以空白分隔的词，`~` 与结束引号及非负整数紧贴；`~0` 表示不允许额外间隔字符。名称模式没有邻近查询功能。

## 12. 多个过滤条件怎样组合

```text
(试运行 | 验收) ext:pdf;docx dir:~/Documents dm:本月 size:<20m
```

名称中含试运行或验收；格式为 PDF 或 DOCX；位于 Documents 范围；本月修改；文件小于 20 MiB。

```text
in (试运行 | 验收) -作废 ext:pdf;docx dir:~/Documents dm:本月
```

正文条件是含试运行或验收、且不含作废；其他条件筛选文件元数据。

组合规则：

- 不同种类的过滤条件同时满足，即 AND。
- 多个 `dir:` 取并集；多个扩展名或类别值也取并集。
- 多个 `size:` 或 `dm:` 取交集。
- 过滤条件从表达式中抽出，作为全局条件使用，**不是每一个 OR 分支各有一套过滤条件**。
- `-dir:…`、`-ext:…`、`-kind:…` 不实现对应的负向过滤，不要这样排除目录或后缀。

例如下面的写法不能表达“Documents 中的甲，或者 Downloads 中的乙”：

```text
(甲 dir:~/Documents) | (乙 dir:~/Downloads)
```

它的目录条件会合并成全局并集，实际相当于在两个目录中查询甲或乙。需要每个分支有不同范围时，请分两次查询。

内容模式必须有正文表达式。只写 `in ext:pdf dir:~/Documents` 不会列出所有 PDF；如果只是按属性找文件，应切回名称模式。

## 14. 与搜索有关的界面操作

以下以快捷启动器为主；快捷键使用 macOS 符号：`⌘` 为 Command，`⌥` 为 Option，`⇧` 为 Shift。

| 操作 | 用途 |
| --- | --- |
| `⌘1` / `⌘2` | 切换名称／内容模式；完整窗口也支持 |
| `⌘/` | 启动器语法速查 |
| `↓` / `↑` | 在结果列表移动；名称列表第一项再向上可回输入框 |
| 在输入框按 `Tab`，当前选中的是文件夹 | 名称模式将该文件夹变成范围标记，随后在其后代项目中进行名称搜索 |
| 在输入框按 `Tab`，当前选中的是应用 | 名称模式按该应用声明可打开的文档类型筛选；不是搜索应用内部数据 |
| 输入为空时按删除键 | 启动器优先移除范围标记；没有范围标记且在内容模式时，移除“内容”标记回名称模式 |
| `Return` | 打开选中的结果 |
| 名称模式 `⌘Return` | 在 Finder 中显示选中项目 |
| 内容模式 `⌘Return` | 进入阅读窗口并定位当前命中 |
| 名称模式的结果列表获得焦点后按 `Space` | 启动器打开系统 Quick Look；输入框中的空格仍是输入文字 |
| 内容模式 `⌘G` / `⌘⇧G` | 在内容预览中前往下一个／上一个命中 |
| 启动器 `⌘E` | 转到完整搜索窗口 |
| 启动器 `⌘,` | 打开设置 |

Tab 对文件夹的范围操作与 `dir:` 类似；对应用的范围操作依赖应用的文档类型声明，不等于一个 `kind:` 类别。完整窗口还可能叠加侧栏目录、类型及时间条件，排查结果时要一并检查。

## 15. 搜不到时的排查顺序

1. 先看模式：要找文件名用名称模式，要找正文用内容模式。
2. 简化为一个有辨识度的普通词，检查是否因多词 AND、排除、时间或类型条件过滤掉结果。
3. 看语法开关与“无法识别”提示。无效的名称正则、类别或元数据过滤可能不发挥预期限制，不能把仍有结果理解为过滤已成功。
4. 内容模式中的 `kind:` 改成 `ext:`；`dir:` 使用完整路径。
5. 目录名片段要匹配完整层级名；含空格的路径用引号包住。
6. 使用通配符时检查整段匹配规则，尤其是名称末尾是否还多了“项目”等文字。
7. 核对名称索引范围、内容索引范围、排除规则、文件访问权限，以及该格式是否完成提取。名称可搜不等于正文可搜。
8. 内容搜索检查匹配模式。宽松模式折叠大小写、兼容字符并合并空白；严格原文逐字符比较的是提取文本，不是 PDF 或 Office 的视觉排版或二进制原文件。
9. 图片或扫描 PDF 依赖实际 OCR 提取状态，提取失败、尚未完成或识别错误的文字不会凭空出现在索引中。
10. 启动器名称结果默认有数量上限。大量同词结果可用 `kind:`、`dir:` 或 `ext:` 缩小范围，或转完整窗口；“未显示在前几项”和“不匹配”需要区分。

当前没有独立的 `name:`、`path:`、`type:`、`created:`、`before:`、`after:`、`case:` 搜索指令，也没有 `find` 前缀或 SQL 式 AND/OR 关键字。需要路径条件用 `dir:` 或路径通配符／路径正则；需要时间条件用 `dm:`；需要内容大小写规则到设置或完整窗口切换。
