## M4-1 网页与电子书

- 新增内容类型 `web`（html/htm/xhtml/shtml）、`ebook`（epub）、`rtf`。HTML 不再按纯文本索引。新类型会出现在提取器指纹里，已经索引过的 HTML 会自动重新提取。
- `xs-parsers::web`：
  - HTML：自己写的容错扫描器，不依赖 HTML5 解析库。
    - 去掉 script、style、noscript、template、svg、math、object 和注释。
    - 块级元素各起一段；单元格用制表符分隔；`<pre>` 保留换行，其余空白合并。
    - 解码实体（数字实体和常见命名实体）；未知或残缺的实体、不构成标签的 `<` 按原样保留。
    - 编码优先用 `<meta charset>` 声明的，否则走 BOM / UTF-8 / GB18030 检测。
    - 每个非空段落一个锚点。
  - ePub：
    - 按 container.xml → OPF → 书脊（spine）的顺序读章节，每章一个以首个标题命名的锚点（没有标题时用“第 n 章”）。
    - container 和 OPF 用宽松的标签扫描读取，不用严格的 XML 解析器：真实文件里有未声明的命名空间前缀和 `&nbsp;`。
    - 支持 Apple Books 的文件夹形式（提取器层面）。
    - 结束记录里条目数写错的 zip，在内存中修正后再打开（`open_zip`，M4-2 也会用）。
    - 没有 container 的“txt 压缩包”（扩展名是 .epub）按文件名的自然顺序读取，method 记为 `epub/loose`。
- RTF：Swift `NSAttributedString`（.rtf），失败时改用 textutil，和 .doc 共用 `attributed()`。
- OFD 补充：纯扫描页（只有 ImageObject、没有文字）标为等待 OCR，部分页是扫描页时标为部分完成（提取器 v2）。
- 内容范围的类型迁移：保存范围时同时记录 `knownTypes`，以后新增的类型默认启用；没有这个字段的旧数据按 M2 的四种类型处理。这修正了 M3 新增类型对已保存范围不生效的问题。
- 预览边栏：行锚点按 `line` 字段显示（之前读的是 `index`，会显示成“行 0”）。

## M4-2 压缩包

- 新增内容类型 `archive`：zip、tar、tar.gz / tgz、gz（单个文件）、7z、rar。
- **简化处理**：一个压缩包算一份内容文档，各成员的正文按包内顺序拼接。每个成员开头有一个部件锚点，名字是它在包内的路径；成员自身的锚点改写为“名称 · 第 3 页 / 段 12 / Sheet1!B3”。预览和阅读窗口据此定位到成员和成员内的位置。ARCHITECTURE §10 设想的“每个子文件单独作为一条结果”（虚拟 file_id、容器链路径）需要改动目录结构，暂未做。
- Rust `xs-parsers::archive::unpack`：
  - 只解包扩展名属于可提取类型的成员，写到临时目录，文件名用序号加原扩展名，所以包内路径不会落到文件系统上（不存在路径穿越的问题）；
  - 限制：单个成员 ≤ 单文件上限，总量 ≤ maxUnpackedBytes（256 MB），成员数 ≤ 5000；按实际读出的字节数计算，头部声明的大小不可信；
  - 只读一层，包内的压缩包跳过；
  - 加密的成员计数后跳过，结果标为部分完成；rar 分卷只从第一卷读，后续分卷给出提示；
  - zip 和 tar 的成员名：是合法 UTF-8 就按 UTF-8，否则按 GB18030（中文 Windows 工具不设 UTF-8 标志），避免被 zip 库当成 CP437 而出现乱码；
  - zip 打开失败时沿用 M4-1 的条目数修复。
- Swift `Extractor.archive`：每个成员交给现有的提取器（所以 PDF、doc、docx、xlsx、ePub 等在包里同样能搜到）。处理时间控制在 20 s + 1.5 s/MB 以内（工作进程的超时是 30 s + 2 s/MB），超时就停下，标为部分完成。压缩包本身不受单文件上限限制。
- 依赖：tar 0.4.46、flate2、sevenz-rust2 0.24.1（加 deflate 特性）、unrar 0.5.8（编译 UnRAR 源码）。UnRAR 许可全文在 `LICENSES/UnRAR-license.txt`，第三方声明已更新。
- 开发：`xs-extract --probe 文件…` 只输出统计（不输出文件名和正文）；`cargo run --example archprobe` 只统计解包结果。
