# M4 计划

ARCHITECTURE §18 对 M4 的要求是“根据实际文件占比安排优先级”。下面的数字来自本机文件名索引的统计（约 13.9 万项，2026-10-30），只统计数量，不涉及文件名和内容。

| 类型 | 数量 | 现状 |
|---|---|---|
| HTML | 577 | 当作纯文本索引，标签和脚本混在正文里 |
| zip / tar / gz / 7z | 515 | 不提取 |
| rar | 384 | 不提取；需要 UnRAR（专有许可，允许解压） |
| ePub | 205 | 不提取 |
| OFD | 49 | M3 已支持；49 个真实文件都能读出，其中 3 个是纯扫描件（等待 OCR，M6） |
| 旧版 PPT | 19 | 不提取 |
| RTF | 16 | 不提取 |
| WPS / ET | 16 | 不提取 |
| eml / emlx | 2 | 不提取 |
| 外置卷、网络盘 | 当前没有挂载 | — |

另外，大量 docx（5,886）、xlsx（3,830）、doc（3,616）、pdf（2,597）不在内容索引范围内（目前范围只有“下载”）。扩大范围不需要开发，在设置里添加文件夹即可。

## 建议顺序

| 块 | 内容 | 依据 |
|---|---|---|
| M4-1 网页与电子书 | HTML（去掉标签、脚本、样式，按段落建锚点）、ePub（按书脊顺序，以章节为锚点）、RTF（textutil 或 NSAttributedString） | 合计约 800 个，实现成本低 |
| M4-2 压缩包 | zip / tar / tar.gz / 7z 里的子文件，用“容器链”虚拟路径表示（`包.zip!/目录/文件.docx`）；预览和定位到子文件；限制层数、总解包大小和子文件数 | 约 500 个；rar 另作决定 |
| M4-3 实时扫描 | 对还没有内容索引的目录显式触发扫描（只扫文本类文件），显示扫描范围、进度和是否已扫完；遵守排除规则 | §8.7 |
| M4-4 WPS 与旧版 PPT | 先按 .doc 的提取路线试 .wps / .et；旧版 PPT 先调研 | 合计约 35 个，按调研结果决定 |
| M4-5 外置卷与网络盘 | 外置卷按卷 UUID 单独分区，拔出后结果标为“离线”；网络盘定期对账 | 当前没有挂载，放在后面 |
| 可选 | 邮件、`xs mcp` 接口 | 邮件只有 2 封；MCP 需要用户主动开启 |
